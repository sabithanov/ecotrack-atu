# EcoTrack ATU — цифровая система управления пищевыми отходами университетского комплекса

**Хакатон ATU «Smart Food Industries» · Трек 1 · Digital Food Waste Management System for University Campuses**

EcoTrack ATU заменяет бумажные таблицы учёта пищевых отходов АО «АТУ». Данные вносятся со смартфона на месте образования отходов, проходят проверку, собираются в единый реестр, а затем в отчёты и аналитику, включая CO₂-эквивалент.

> **Қысқаша (қаз.):** EcoTrack ATU — университет кешенінің тағам қалдықтарын есепке алудың цифрлық жүйесі. Деректер смартфоннан енгізіледі, тексеруден өтеді, бірыңғай тізілімге түседі, Excel-ге жүктеледі және дашбордта талданады. Интерфейс қазақ және орыс тілдерінде.

## Полный цикл MVP

```
Форма (смартфон / QR) → проверка значений → отправка отчёта → проверяющий: принять / вернуть с комментарием
        → единый реестр (только принятые) → dashboard и отклонения → сводный отчёт (месяц / квартал / год) → Excel / PDF
```

## Как запустить

**Вариант 1. GitHub Pages (публичная ссылка, работает на смартфоне)**
Settings → Pages → Source: *Deploy from a branch* → Branch: `main` / `(root)` → Save. Через 1–2 минуты сайт откроется по адресу `https://<логин>.github.io/<репозиторий>/`.

**Вариант 2. Локально на ноутбуке (Windows, без установки Node/Python)**
```powershell
powershell -ExecutionPolicy Bypass -File serve.ps1
```
Затем откройте http://localhost:8080.
Подойдёт и любой другой статический сервер: `npx serve`, `python -m http.server 8080` и т. п.

**Демо-данные** создаются автоматически при первом открытии. Сбросить их можно так: «Администрирование → Настройки и данные → Сбросить к демо-данным».

## Сквозной демо-сценарий (раздел 9 ТЗ)

1. Смартфон: отсканировать QR-код столовой (или открыть ссылку) и войти как `iskander@atu.kz`.
2. Внести 2–3 взвешивания: плитка вида отхода → вес → «Сохранить запись». Итоги за день и месяц пересчитываются сразу.
3. «＋ Новый вид отхода»: например, «Хлебные отходы».
4. «Отправить отчёт на проверку»: статус «Отправлено».
5. Ноутбук: войти как `reviewer@atu.kz`, «Проверка отчётов» → отчёт столовой → «Вернуть с комментарием».
6. Смартфон: появляются статус «Возвращено» и комментарий. Исправить запись → «Отправить повторно». Проверяющий нажимает «Принять», и в истории видны все шаги.
7. «Реестр»: фильтры по организации, периоду и виду отходов.
8. «Dashboard»: 5 графиков, отклонения, рекомендации, CO₂.
9. «Сводный отчёт» → Квартал → «Excel».
10. Там же — блок «Не сдали отчёт» (в демо-данных это ТХиПП, возвращён, и Canella, ожидает проверки за октябрь).

Подробный сценарий с таймингом: [docs/DEMO.md](docs/DEMO.md).

## Облачная синхронизация (смартфон ↔ ноутбук)

Без настройки приложение работает в **локальном режиме**: данные хранятся только в браузере. Чтобы смартфон ответственного лица и ноутбук проверяющего работали с общими данными, подключите бесплатный проект Supabase:

1. Зайдите на [supabase.com](https://supabase.com) → **New project** (регион — например, Central EU).
2. **SQL Editor → New query** → вставьте [supabase/setup.sql](supabase/setup.sql) → **Run**.
3. **Project Settings → API**: скопируйте **Project URL** и публичный ключ **anon / publishable** в [js/config.js](js/config.js). Секретный ключ `service_role` / `secret` туда не вставляйте.
4. Загрузите сайт на GitHub Pages и откройте его. Первое устройство само загрузит демо-данные в облако, остальные подтянут их оттуда.

Индикатор в шапке: **☁ онлайн** — данные общие, **☁ офлайн** — нет сети (записи сохраняются локально и отправляются при появлении связи), **локально** — облако не настроено. Изменения других устройств приходят примерно за 4 секунды. Подключить облако можно и без правки кода: «Администрирование → Настройки и данные → Облачная синхронизация».

**Как это устроено:** каждая запись (организация, пользователь, вид отхода, отчёт, взвешивание, история) хранится строкой в таблице `ecotrack_records` (JSON + `updated_at`, который ставит сервер). Клиент отправляет только изменённые записи (upsert), а раз в 4 секунды забирает чужие изменения. Удаление сделано мягким (`deleted = true`).
**Ограничение MVP:** права ролей проверяются в слое API клиента, а таблица открыта для публичного ключа на чтение и запись (физическое удаление запрещено). Для промышленной эксплуатации подготовлена схема с серверными функциями и Row Level Security по ролям: [supabase/schema.sql](supabase/schema.sql).

## Архитектура

* **Клиент:** PWA на чистом HTML, CSS и JavaScript без сборки, работает с GitHub Pages и офлайн.
* **Слой API** (`js/api.js`): единственная точка доступа к данным. Каждый метод проверяет сессию, роль и принадлежность к организации; UI только показывает результат. Пароли хранятся как солёный хэш (300 итераций SHA-256).
* **Хранилище:** локальная копия в localStorage (офлайн), которая синхронизируется с облаком Supabase (PostgreSQL) через REST (`js/sync.js`). **Пилот:** нормализованная схема с серверными функциями переходов статусов и Row Level Security по ролям ([supabase/schema.sql](supabase/schema.sql)).
* ER-диаграмма, процессы «как есть / как будет», формулы расчётов: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).
* Экономика и экология: [docs/ECONOMICS.md](docs/ECONOMICS.md).
* Пример сводного отчёта за квартал по всем организациям (выгружен из системы): [docs/Сводный_отчёт_3_квартал_2026.xlsx](docs/Сводный_отчёт_3_квартал_2026.xlsx).
* Финальная презентация: [presentation/EcoTrack_ATU_presentation.pdf](presentation/EcoTrack_ATU_presentation.pdf) (исходник — `presentation/index.html`, печать в PDF из Chrome: поля «Нет», фон «Вкл»).

## Коэффициенты CO₂ (ФТ-6.5)

Источник: UK DESNZ / DEFRA *Greenhouse gas reporting: conversion factors 2024*, раздел *Waste disposal*. Значения приближённые, их можно изменить в справочнике видов отходов.

| Категория | Полигон (захоронение), кг CO₂-экв./кг |
|---|---|
| Пищевые / органические, отработанное масло | 0,70 |
| Картон / бумага | 1,04 |
| Пластик, стекло, металл | 0,009 |
| Переработка / компостирование (любая категория) | 0,01 |

Отработанное масло переводится из литров в килограммы с плотностью 0,92 кг/л.
